# 第二层处理：基于已有数据构建增强图谱

## 输入审计与边界

实际第一步目录为 `data/rasbt__mlxtend/20261101-185034-cc52d0-git-5c8a9e`。
程序先验证 manifest 中全部 processed 校验和，生成 reports/input_audit.json。原目录不修改。

第一步有 15,409 个节点、66,660 条边。13 类节点文件中 Module/Feature/Problem/Solution 为空。
节点结构为 id/entity_type/properties/provenance；关系端点为 source_id/target_id，证据是 evidence_ids。
processed/evidence.jsonl 的 raw_ref 和 json_pointer 指向原始 API/Git 记录，不应把 evidence 字段中的通用说明当作原文引用。
processed/documents.jsonl 的 raw_text 是语义证据定位基准，字符位置采用 Python Unicode code point 半开区间。
code_versions 仅绑定 reference_sha；不能拿当前行号套到历史提交。
file_changes 的 Git 记录有 old_blob/new_blob；API fallback 记录可能有 patch，但不能保证对应历史源码可读取。
本次已有 Git 缓存可离线读取；第二层没有 fetch、clone 或 GitHub 请求。

## 启动

从 archaeologist-ui 目录运行：

```powershell
python second_stage.py --source data/rasbt__mlxtend/20261101-185034-cc52d0-git-5c8a9e --output data/rasbt__mlxtend_layer2 --workers 8
```

仅离线规则处理：追加 `--offline`。
小批量验证：追加 `--limit 10`（仍执行完整离线处理和功能目录生成）。
其他仓库必须使用 `--git-cache` 指定其已有裸仓库。

依赖 Python、Git，以及示例已经使用的 openai/python-dotenv。
读取项目根目录 `.env` 的 API_KEY、API_URL、MODEL，不把密钥写进产物。
API_URL 可为 SDK base URL，或完整的 /chat/completions 地址；程序移除重复端点后缀。

## 处理内容

1. 从现有 Python 包路径生成规则 Module。
2. PR 正文明确行首 Fixes/Closes/Resolves #N 生成 RESOLVES；未合并 PR 标 candidate。
3. 冻结 tag 的 Git 可达集合，按正式 Release published_at 排序生成 FIRST_RELEASED_IN。不根据 commit 时间猜测，不给 API-only SHA 强行归属。
4. 批量读取本地历史 blob，解析提交前后 AST，按实际增删行定位 CHANGES。合并提交沿用第一父版本策略。历史解析失败计入质量报告。
5. 从仓库文档提出最多 20 个 Feature。它们标记 llm_proposed，不冒充人工确认。目录输入最多 50,000 字符，每份文档最多 6,000 字符。
6. 对全部 Issue/PR 组装正文、关联 Issue 和评论，每 18,000 字符拆分，不丢弃剩余文字。候选代码符号最多 80 个；这不是完整代码语义验证。
7. 调用模型提取 Problem、Solution、目录内 Feature 变化；校验类型、枚举、实体候选和逐字证据。原文证据写 document_id/raw_start/raw_end。
8. 模型高置信度 Problem/Solution 关系标 inferred；功能变化、功能实现和方案实现仍标 candidate。SOLVES 通过明确修复链生成候选，再由 verify_semantics.py 依据原文复核；复核通过且置信度至少 0.9 才标 inferred，其余保持 candidate。模型复核不等于人工确认。
9. 兼容第一步节点/关系格式输出，执行原有结构校验，失败项进入 review_queue。

## 输出和恢复

- processed/nodes/*.jsonl：原有实体＋新增实体。
- processed/relations.jsonl：原有关系＋新增关系，含 candidate，请查询时明确过滤 status。
- processed/evidence.jsonl：原证据定位改为原数据包的绝对路径，保留原数据包才可追溯。本输出不是可脱离原包搬运的独立 ZIP。
- processed/historical_code_versions.jsonl：历史符号、before/after、blob SHA、文件和行号。
- processed/documents.jsonl、chunks.jsonl：原文与检索块。
- semantic/tasks.jsonl：实际模型输入；semantic/candidates.jsonl：候选边。
- llm_cache/*.json：原始响应、模型、输入哈希、提示词版本和 token 用量。
- state/deterministic.json：与输入校验和、代码版本、Git路径绑定的离线检查点。
- reports/quality.json：实体/关系计数、成功/失败任务数、已知限制。

重跑相同命令会复用离线检查点和模型成功缓存。失败请求没有成功缓存，重跑会再次尝试。
缓存保存模型原始输出，不是已验证事实。修改提示词或处理语义时应递增 VERSION。

## 不能宣称完成的内容

第一步缺失的 Git 对象不会被模型补齐；无对象部分不能产生可靠历史函数映射。
跨 Issue 的同义 Problem 尚未自动合并，避免误合并。Feature 提案和候选关系仍需审核。
模型置信度未经标注集校准，不能当成事实正确率。
当前提供知识图谱数据，不安装 Neo4j，也不包含问答 UI。
manifest 保留 partial，避免将上游不完整与候选语义误报成全量事实。
