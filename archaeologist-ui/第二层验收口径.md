# 第二层流程的实际验收口径

- 输入契约：先通过第一步 manifest 中所有校验和，再处理。input_audit.json 记录实际检查结果。
- 原始数据不变：不在第一步目录写入任何数据；所有模型任务、响应、增强实体均写第二层目录。
- 不补爬：Git 只执行本地 cat-file/rev-list；唯一网络操作是用户配置的模型 API。
- 追溯：语义边保留原文片段、文档 ID 和 Unicode 字符偏移；模型原始响应与用量另外缓存。
- 事实分层：api/git/ast/rule 的 asserted、模型抽取的 inferred 和待审 candidate 分开标记。主查询不得默认把 candidate 当事实。
- SOLVES 复核：在明确 RESOLVES 链上生成问题/方案候选，然后再次请求模型根据双方原文判断；通过复核且置信度至少 0.9 才标 inferred。仍不等于人工核验。
- 缺失保留：第一步的 API-only 提交不会伪造本地 Git 对象；没有 AST 的范围记录限制；不声称覆盖全部历史。
- 缓存：输入内容、模型、端点、提示词版本一起决定缓存键；重跑不重复调用相同成功任务。
- 输出是知识图谱数据包，不是已部署 Neo4j。
