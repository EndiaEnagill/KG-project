# 全量采集模式（desktop-4）

界面已移除Issue、PR、Commit、Release、评论、源码文件数量输入框。输入仓库链接、Token和保存目录，点击开始即可。无需重新安装依赖，关闭旧窗口后重新双击启动工具。

## 本次全量的准确范围

- 全部可访问的open/closed Issue，不将PR重复当Issue。
- 全部可访问的open/closed/merged PR，以及普通评论、Review和行内评论。
- PR原始提交、合并结果、默认分支提交，以及分支和tag可达提交；按SHA去重，不设全局数量预算。
- 全部GitHub Release对象、分支和tag列表。
- 默认分支冻结SHA的完整文件树和可通过blob API读取的文件内容；解析所有Python文件，提取全部可解析类、函数和方法。
- 冻结快照下的全部Markdown、RST和TXT文档，不再只取根目录前5份。
- 逐Commit文件分页不再人为限制10页。PR提交与Commit文件可能受GitHub端点硬上限影响，疑似不足会报告partial，需要Git补齐，不能宣称平台数据无遗漏。

全量不是“读取GitHub所有产品信息”：当前不采Discussion、Actions日志、Release二进制附件、Wiki、外部LFS对象、子模块内容、不可达或已删除提交，也不保存每一个历史版本的完整源码快照。非Python文件可归档，但不进行AST解析。API采集不是原子快照，采集期间远端变化可能需要后续新任务复查。

## 结果如何理解

manifest中的mode为full，scope各项为null（无人工数量限制）。ready表示声明范围的受支持采集步骤没有记录失败或截断，不代表语义图谱全部完成。未实现的语义抽取、历史符号映射和发布归属仍标not_run。

新增processed/refs.json保存分支与tag，source_tree.json保存默认分支源码树。raw/api里归档blob原始内容（包括二进制内容的base64），raw/source里另存用于AST解析的Python文本。归档失败、解码失败、解析失败均记录，不把错误当作不存在。

任务可能较长。出现权限/限流后，查看日志与quality报告，稍后使用“恢复已有任务”继续，复用成功缓存；取消会保存已处理结果。恢复旧版有界任务也会改用全量模式，原始缓存复用，标准化文件重建。人工配置结果建议保留其configured副本，不在配置后的目录恢复网络采集。

旧结果不会因为更新工具自动变全量，需要新建或恢复任务。语义处理与Module/Feature配置仍为独立步骤。
